# Existing-project continuation audit

The final plan recheck found a concrete omission in existing-project support: each new run reused the initial cycle directory. The completed validation projects each used their own directory, so their recorded scientific results do not exercise or resolve this defect. A regression first reproduced the collision before the fix.

Cycle numbers are now reserved across the project, considering both SQLite records and existing directories. Attaching a public clone therefore preserves its archived results even without private execution state. The controller serializes project writers, counts the current run's cycles separately from directory numbering, and includes earlier findings and evidence locations in new prompts. Rendering a selected cycle attributes its paper to the recorded backend rather than whichever run happens to sort last.

The budget-boundary test also caught a problem while implementing this repair: a saved hypothesis-revision decision could be lost when the cycle allowance ended. That transition is now durable. Extending the allowance starts the requested new cycle without repeating the accepted review, and leaves the earlier incomplete cycle and observations intact. No live inference or retraining was used for this audit.

The tests exercise real fake-CLI subprocesses across research cycles, preserve archived bytes, migrate older state without resetting counters, reject concurrent project ownership and select the correct backend with or without SQLite. See [the regression tests](../tests/test_continuation.py), [public-clone tests](../tests/test_public_clone.py), and [saved full-suite result](offline-tests.xml). The generated [validation summary](validation-summary.md) reads the test count directly from that result file. Allocation uses SQLite's documented [immediate write transactions](https://www.sqlite.org/lang_transaction.html#deferred_immediate_and_exclusive_transactions); no external implementation code was copied.

The [recheck receipt](verification/continuation-recheck.json) identifies the tested source revision and file hashes, locked fresh-clone installation, [fresh-clone test output](continuation-fresh-clone-tests.xml), unchanged numerical regeneration without private workspaces, public trial artifact hashes, phase verification, shared collection membership and environment checks. The regenerated paper's changed page was visually inspected; its other rendered pages match the previous visual inspection pixel for pixel. Git-normalized repository bytes are used for the root HTML comparison, rather than treating local newline conversion as a deployment change.

The plan's completed scientific executions and public artifact checks remain in [final checks](final-checks.md). This repair adds offline evidence for continuing existing projects; it does not establish broad scientific reliability. The documented limits remain: classification-specific numerical reporting, provider identities absent from Codex events, possible orphan cleanup after a hard OS crash, and semantic research judgment beyond structural evidence checks. Optional or inapplicable outputs are explained in the [requirement map](../docs/acceptance.md).
