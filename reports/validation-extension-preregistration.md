## Objective and decision rules

The primary engineering outcome is whether each run completes all required phases with verifiable public artifacts. The competing explanation is that additional time merely permits repeated formatting repairs without achieving valid artifacts. Record phase acceptance, active time, calls, repair reasons and publication receipts. Success requires public-clone verification, regeneration, checkpoint loading, PDF inspection and browser interaction. Failed, incomplete and inconclusive outcomes remain publishable. No provider ranking or broad scientific reliability claim will follow from these executions.

Haiku resumes its existing run, with its existing observations and consumed counters, under a total allowance of 180 active minutes and 60 CLI calls. Sonnet (`sonnet`) and Sol (`gpt-6.1-sol`, explicitly chosen by the user) each receive the same total allowance in new, separate projects. Run them sequentially after the Haiku continuation. The larger allowance is an engineering choice, not an empirically optimized threshold. No automatic extension or model substitution occurs. All model work, including review, uses the selected backend and model. Report requested versus actually exposed identities separately.

## Scientific interpretation

Prior digits outcomes are known. The new trials are exploratory engineering replications, not new confirmation on untouched data. Keep the original split, normalization, architecture, optimizer, learning rate, batch size, epochs, decay settings, seeds, baselines, shuffled-label control and conditional bootstrap procedure. Only prospective replication metadata and evidence classification change. Freeze each new protocol and publish tested core before training. Publish the seed-zero validation pilot before comparisons. Never select configurations using test outcomes.

Haiku's historical protocol and result classifications remain unchanged; its additional analysis and interface repairs are post hoc. Do not repeat training merely to repair a path or handoff. Keep the original deadline outcome separate from the extended final outcome. Record harness changes and external repairs so additional success is not misrepresented as an uninterrupted frozen-version trial.
