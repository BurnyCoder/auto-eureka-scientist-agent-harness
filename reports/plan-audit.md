# Implementation and execution audit

This audit separates implemented capabilities from evidence of completed executions. The original Haiku run did not complete its bounded protocol; Luna completed controller phases but needed disclosed post-run provenance repairs. The user's new instruction authorizes an extension and additional models, recorded prospectively in [the addendum](validation-extension-preregistration.md). Results will be generated from saved execution summaries, not inferred from intent.

## Confirmed defects and changes

Haiku transcripts show repeated failures over cycle-relative versus project-relative paths, optional empty handoff fields, duplicate experiment identifiers in a separate evidence ledger, and unsupported confirmatory classifications. The first categories waste interaction time; the last category is a substantive scientific problem. Paths now resolve from either root when unambiguous, Claude's empty optional fields receive explicit defaults, prompts supply a complete example, and agents can run a draft verification command inside the same invocation. Classification and factual provenance checks remain. A larger explicitly recorded budget permits continuation without erasing the original cutoff.

The publication audit found that PR merging did not wait for reported checks, and model upload deduplication keyed numerical metrics rather than actual uploaded files. The publisher now waits for reported checks at the intended commit and fingerprints every uploaded artifact. Empty check lists are not represented as evidence that CI ran. Native CLI null events no longer crash parsing. Current study source must match its core receipt. Resume recovery uses the same search/comparison checks as fresh responses. New known-result replications retain exploratory classification. Baseline reports no longer attribute neural optimizer settings to logistic regression or class-prior methods.

An initial suspicion about cross-cycle verification was disproved by inspection: SQLite already selects the current cycle. No fix was necessary for that behavior.

## Plan coverage and limits

The [requirement map](../docs/acceptance.md) links the original prompt to implementation and artifacts. The test suite covers CLI adapters, full-stream transport, Unicode paths, retries, interruption, state recovery, scientific checks, numerical regeneration and publication receipts. The original policy bytes are unchanged. Scope, preregistration, core publication, pilot publication, experiments, analysis, review and final publication remain the operational phases. Neel Nanda's research stages and pre/post-experiment reflections remain in phase prompts and durable handoffs.

General orchestration is implemented, while live scientific validation is specific to the bundled classification study. Arbitrary research domains require domain-appropriate metrics and verification; the current reporting engine must not be described as universal. Source retrieval proves access, not semantic truth. A hash proves artifact identity, not correct science. CLI identities/costs absent from provider events remain unknown. Hard process crashes can leave orphan cleanup work. Offline contract tests do not establish broad autonomous reliability.

The supervised digits study has loss curves but no reward objective. Writer-level generalization and concept-swapping experiments are not supported by this protocol. The harness has no trainable weights; validation checkpoint bundles are uploaded. The shared Hugging Face collection follows the user's revised instruction. Public raw transcripts remain excluded to avoid publishing credentials or private tool output; sanitized summaries and reproducible artifacts are published.

Final acceptance requires additional observed runs and public artifact checks; code changes alone do not mark that work complete. Any manual repair and any unmet requirement must remain explicit in the final report.
